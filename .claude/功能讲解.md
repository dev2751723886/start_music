## 一、数据库：数据都存在哪

**文件：`until/DBuntil.java`**

这个类是「数据库的入口」。它管两件事：**建库、建表**。

里面有几张表（就是几个"表格"）：

| 表名 | 存什么 | 关键字段 |
|---|---|---|
| `d_user` | 账号 | account(账号)、nickname、pwd、sex... |
| `d_sheet` | 歌单 | id、name(歌单名)、img(封面)、create_user_id、sta |
| `d_music` | 歌曲 | id、name(歌名)、singer、img、path(音频)、sheet_id、**love(是否喜欢)** |
| `d_music_play` | 正在播放 | id(歌曲id)、user_id、sta |

**版本号机制（重要）：**

```java
private static final int version = 12;  // 每次改表结构 +1
```

- 第一次装 App：走 `onCreate`，把表全部建好。
- 老用户升级 App：走 `onUpgrade`，根据旧版本号，用 `ALTER TABLE` **补加**新字段，不清空老数据。

比如我们做「收藏」时，把 `d_music` 表加了 `love` 字段，就是版本号 11 → 12，在 `onUpgrade` 里加了一句：

```java
if (oldVersion < 12) {
    db.execSQL("ALTER TABLE d_music ADD COLUMN love VARCHAR(50) DEFAULT '0'");
}
```

## 二、SqliteT：通用查询工具（你问的这个）

**文件：`until/SqliteT.java`**

### 它是什么？

它**不是**「查音乐」的功能，而是一个**「执行 SQL 并把结果塞进对象」的通用工具**。谁要查数据，就调它。它自己不关心查的是歌曲还是歌单还是用户。

打个比方：`SqliteT` 是「跑腿的」，`MusicDao` 是「点菜的」，`MusicDao` 告诉它「去查所有歌」，它就跑 SQL、把查到的每一行自动装进 `MusicBean` 对象里。

### 核心原理：反射

最核心的方法是 `query`：

```java
public static <T> List<T> query(String sql, Class<T> clazz, String ...data) {
    Cursor result = db.rawQuery(sql, data);   // 1. 执行 SQL，拿到结果集
    List<T> list = new ArrayList<>();
    while (result.moveToNext()) {              // 2. 一行一行遍历
        T t = clazz.getDeclaredConstructor().newInstance();  // 3. new 一个空对象
        Field[] fields = clazz.getDeclaredFields();          // 4. 拿到这个类的所有属性
        for (Field field : fields) {
            field.setAccessible(true);
            String name = field.getName();                   // 属性名，比如 "name"
            String value = result.getString(result.getColumnIndex(name)); // 按同名列取值
            field.set(t, value);                             // 5. 塞进对象
        }
        list.add(t);
    }
    return list;
}
```

**一句话总结它怎么做的：**

> 数据库列名 和 类属性名 **一致**，它就「按名字对号入座」——用反射读类的属性名，再去结果集里找同名列，把值塞进去。

所以你的 `MusicBean` 里属性名是 `name`、`singer`、`img`、`path`、`sheet_id`、`love`，数据库列名就必须叫 `name`、`singer`、`img`、`path`、`sheet_id`、`love`，对上了就能自动填。**这就是为什么加 `love` 字段时，`MusicBean` 里也要加一个 `love` 属性**（再加对应的 get/set）。

### 它提供的方法

| 方法 | 干嘛 |
|---|---|
| `query` | 查多条，返回 List |
| `queryOne` | 查一条 |
| `updata` | 执行 update/delete（改数据） |
| `queryMapList` / `queryOneMap` | 查出来放 Map 里（不用 bean） |

## 四、播放功能（顺序/随机 + 封装思路）

**文件：`activity/yonghu/UserActivity.java`** —— 这是播放的**中心**，播放条也在这里。

### 关键字段

```java
private MediaPlayer mediaPlayer;        // 真正播放音频的家伙
private List<MusicBean> currentPlaylist; // 当前播放的歌曲列表
private int currentIndex = 0;            // 当前播到第几首
private boolean randomMode = false;      // false=顺序  true=随机
private MusicBean currentMusic;          // 当前正在播的那首（收藏要用）
```

### 两个「播放入口」（对外被调用）

1. **`playSheet(sheetId)`** —— 点推荐歌单的播放按钮时调用，播这个歌单的**第一首**：

```java
public void playSheet(String sheetId) {
    List<MusicBean> songs = MusicDao.getMusicBySheet(sheetId);
    currentPlaylist = songs;   // 记下整个歌单
    currentIndex = 0;          // 从第一首开始
    playMusic(songs.get(0));
    PalymusicDao.saveCurrentPlayMusic(...); // 记录"正在播放"
    showPlayer(songs.get(0));
}
```

2. **`playSongList(songs, index)`** —— 点热榜/收藏里的歌时调用，从**点的那首**开始播：

```java
public void playSongList(List<MusicBean> songs, int index) {
    currentPlaylist = songs;
    currentIndex = index;
    playMusic(songs.get(index));
    ...
}
```

### 真正播放：`playMusic(bean)`

```java
private void playMusic(MusicBean bean) {
    int resId = getResources().getIdentifier(bean.getPath(), "raw", ...); // 把音频名转成资源id
    mediaPlayer = MediaPlayer.create(this, resId);   // 创建播放器
    mediaPlayer.setOnCompletionListener(mp -> playNext()); // 播完自动切下一首
    mediaPlayer.start();                             // 开始播
    ...
}
```

> 你的音频放在 `res/raw` 里，`bean.getPath()` 存的是 raw 资源名（比如 "daoshihoushuoaini"），用 `getIdentifier` 把它转成资源 id 才能播。

### 顺序/随机切换：`togglePlayMode()` + `playNext()` + `playPrev()`

**`togglePlayMode()`** —— 点 `bianhua` 按钮，切换 `randomMode`，换图标：

```java
private void togglePlayMode() {
    randomMode = !randomMode;
    if (randomMode) playModeBtn.setImageResource(R.drawable.rand_br); // 随机图标
    else            playModeBtn.setImageResource(R.drawable.sun_br);  // 顺序图标
}
```

**`playNext()`** —— 下一首的算法：

```java
if (randomMode && size > 1) {
    do { next = random.nextInt(size); } while (next == currentIndex); // 随机，且不重复当前
} else {
    next = (currentIndex + 1) % size;  // 顺序：+1，到末尾 % size 就循环回第一首
}
```

**`playPrev()`** —— 上一首，顺序就是 `(currentIndex - 1 + size) % size`。

**`playIndex(index)`** —— 统一切歌入口，`playNext`/`playPrev` 算好下标后都调它：

```java
private void playIndex(int index) {
    currentIndex = index;
    MusicBean bean = currentPlaylist.get(index);
    playMusic(bean);
    showPlayer(bean);
}
```

### 「封装」是怎么回事（你问过的）

你之前问「能不能封装一个类」。我给你做过的解释是：

**`UserActivity` 内部其实已经「复用」得很好了**，没有重复代码：

```
playSheet ─┐
playSongList ─┤
playNext ─────┼──> playIndex ──> playMusic + showPlayer
playPrev ─────┘
```

所有「播放」最终都汇到 **`playMusic`（真正放声音）+ `showPlayer`（更新播放条界面）** 这两个方法上。这就是「封装」的意义：**改一处，处处生效**。

当时我们讨论过要不要把播放逻辑抽成一个独立的单例类 `PlayerManager`，让 `MusicListActivity`（歌单列表页）那套独立的 MediaPlayer 也统一进来。但结论是：**那点重复很小，抽单例反而过度设计，所以最终保持现状**（`UserActivity` 不动，`MusicListActivity` 保留它几行简单播放）。

### 进度条

`UserActivity` 里有个 `Handler`，每 0.5 秒把播放器当前进度同步到 `SeekBar`：

```java
private final Runnable updateSeekBarRunnable = new Runnable() {
    public void run() {
        if (mediaPlayer.isPlaying()) {
            seekBar.setMax(mediaPlayer.getDuration());
            seekBar.setProgress(mediaPlayer.getCurrentPosition());
        }
        handler.postDelayed(this, 500); // 每0.5秒再跑一次
    }
};
```

拖动进度条松手时 `mediaPlayer.seekTo(进度)` 跳到对应位置。

## 七、跳转界面 + 返回按钮

**涉及文件：**
- `adapter_user/PlayMusicAdapter.java` —— 点歌单跳转
- `activity/MusicListActivity.java` —— 歌单歌曲列表页 + 返回按钮
- `res/layout/activity_music_list.xml` —— 列表页布局

### 前进（打开新界面）：用 Intent

`PlayMusicAdapter` 里点歌单卡片：

```java
Intent intent = new Intent(context, MusicListActivity.class);
intent.putExtra("sheet_id", bean.getId());   // 带数据过去
intent.putExtra("sheet_name", bean.getName());
context.startActivity(intent);               // 打开新界面
```

### 返回（回上一个界面）：用 finish()

`MusicListActivity` 里返回按钮：

```java
findViewById(R.id.back_btn).setOnClickListener(v -> finish());
```

### 为什么前进用 Intent、返回用 finish()（你问过的）

Android 用「**栈**」管理界面，像叠盘子：

```
栈顶 → MusicListActivity   ← 点歌单后 startActivity 压进去
栈底 → UserActivity        ← 一直在下面等着
```

- **前进** = 打开**新的**界面 → 用 `Intent + startActivity`（压栈）
- **返回** = 销毁当前界面，露出下面**已经存在的** → 用 `finish()`（弹栈）

如果返回也用 `startActivity(new Intent(UserActivity))`，会**再 new 一个新的 UserActivity**，栈里就有两个 UserActivity，返回键要按两次，还白占内存。所以返回必须 `finish()`。

## 八、一路上踩过的坑（问题 → 原因 → 解决）

### 1. 歌曲列表排版乱、后面的歌看不见

- **文件**：`res/layout/list_music.xml`
- **原因**：有一行 `android:layout_marginTop="-325dp"`，负边距把每首歌的内容往上顶了 325dp，超出 item 边界，导致内容重叠、后面的被挤出视野。
- **解决**：删掉这行负边距。

### 2. 「加了背景就排版乱了」

- **原因**：把 `@drawable/miaomiao`（一张 **852×1781 的竖版全屏壁纸**）设成了**每一首歌 item** 的背景。N 首歌就把这张大图压成 N 条，图案全挤变形，还卡。
- **解决**：背景不能放 item 上，要放到**整页根布局**上。把 item 的背景删掉，改加到 `activity_music_list.xml` 根布局。

### 3. 返回按钮出现在每一首歌上

- **原因**：返回按钮加在了 `list_music.xml`（item 布局）里，每首歌渲染一次就出现一次。
- **解决**：把返回按钮从 item 挪到 `activity_music_list.xml` 顶部（只出现一次），并接 `finish()`。

### 4. 热榜标题离歌曲太远

- **原因**：热榜的 RecyclerView 既有 `marginTop="15dp"` 又有 `padding="15dp"`，叠加成 30dp 间距。
- **解决**：改成 `marginTop="0dp"`，padding 只留左右（跟推荐歌单一致）。

### 5. 点首页返回很卡

- **文件**：`activity/yonghu/fragment/Homefragment.java`、`adapter_user/PlayMusicAdapter.java`
- **原因**：
  1. `Homefragment` 每次进首页都调 3 次 `saveDrawableToFileSaveAs`，每次「解码大图 + PNG 压缩 + 写盘」，是主线程最卡的操作；
  2. `PlayMusicAdapter` 的 Glide 禁用了缓存（`skipMemoryCache(true)` + `diskCacheStrategy(NONE)`），图片每次重新解码。
- **解决**：删掉重复写文件（封面在数据库建库时已写过）；恢复 Glide 默认缓存。

### 6. 封装播放类（讨论后保持现状）

- 原本想抽一个 `PlayerManager` 单例统一播放。但发现 `UserActivity` 内部已经复用得很好，`MusicListActivity` 只有几行重复，抽单例反而复杂。最终**保持现状**，抽出来的文件已删除。

### 一条数据是怎么「流」起来的（串起来看）

以「点热榜一首歌播放」为例，走一遍文件之间的协作：

```
① Homefragment.java 查数据          → MusicDao.getAllMusic()
② 交给 RedMusicAdapter 显示          → 每行绑定 排名/封面/歌名
③ 点击某行 → 回调                   → RedMusicAdapter 的 OnItemClickListener
④ 回到 Homefragment 调 UserActivity  → activity.playSongList(redList, position)
⑤ UserActivity 真正播放             → playMusic() 用 MediaPlayer 放 raw 音频
⑥ 播放条界面更新                    → showPlayer() 改封面/歌名，Handler 刷进度条
```

看懂这条链路，整个 App 就串起来了。

## 十二、这一阶段踩过的坑（问题 → 原因 → 解决）

### 1. 删歌单里的歌，推荐/热榜的歌也一起没了

- **原因**：一开始把「删除歌曲」做成了**全局软删除**（给 `d_music` 打 `deleted='1'` 标记），而推荐歌单、热榜、自己歌单都指向**同一张 `d_music` 表**，于是从所有地方一起消失了。
- **解决**：改成「**从歌单移除**」（`removeMusicFromSheet` 只删 `d_sheet_music` 关系），不动歌曲本身；并把全局软删除 + 回收站整体撤掉。

### 2. 自己创建的歌单混进了推荐歌单

- **原因**：创建歌单时 `sta` 存了 `'1'`，和系统推荐歌单一样，而 `getPlayMusic` 是 `where sta='1'`，所以自己建的歌单漏进推荐。
- **解决**：创建歌单 `sta` 存 `'0'`；再加数据库迁移（版本 16）把老数据里用户自建的歌单统一 `sta='0'`。

### 3. 推荐歌单顺序每次进都不一样

- **原因**：`getPlayMusic()` 里用了 `Collections.shuffle()` 随机打乱。
- **解决**：去掉 shuffle，改成 `order by id` 固定顺序。

### 4. 点全屏播放页闪退（`UnsatisfiedLinkError`）

- **现象**：`No implementation found for ... LrcParser.parseLrc`，报的符号名是 `Java_com_example_music_1star_until_LrcParser_parseLrc`。
- **原因**：包名 `music_star` 里有下划线，JNI 命名里下划线要转义成 `_1`，所以正确符号名是 `music_1star`，我写成了 `music_star`，导致找不到 native 函数。
- **解决**：把 C++ 函数名改成 `Java_com_example_music_1star_until_LrcParser_parseLrc`。

### 5. JNI 返回二维数组类型写错（会 `ClassCastException`）

- **原因**：`parseLrc` 返回 `String[][]`，外层数组应该用 `[Ljava/lang/String;`（String[]）当元素类型，结果写成了 `java/lang/String`，Java 接收时类型对不上。
- **解决**：`FindClass("[Ljava/lang/String;")` 建外层数组，内层才是 `java/lang/String`。

> **JNI 两个易错点（牢记）**：① 函数名里的下划线要 `_1` 转义；② 二维数组外层元素类型是 `[Ljava/lang/String;`，不是 `String`。
